INTRODUCTION                                        *terminals-introduction*

terminals.nvim manages the persistent window objects returned by Snacks
Terminal. Terminals are ordered by creation time, selected circularly, and
shared across tab pages. Each normalized working directory and window position
has an independent terminal group and active selection.

==============================================================================
REQUIREMENTS                                        *terminals-requirements*

Snacks is a required dependency:

    https://github.com/folke/snacks.nvim

For lazy.nvim (replace OWNER with the repository owner): >lua

    {
      "OWNER/terminals.nvim",
      dependencies = { "folke/snacks.nvim" },
      opts = {},
    }
<

==============================================================================
SETUP                                                      *terminals-setup*

Setup is optional. The defaults are: >lua

    require("terminals").setup({
      width = 220,
      win = {
        position = "float",
      },
    })
<

`width` is the window width in characters. Snacks clamps it when necessary.
`win` accepts additional snacks.win options. `win.position` is the default
position and may be "float", "top", "bottom", "left", or "right". Snacks'
buffer-replacing "current" position is not part of the supported contract.
The shared width and other options affect terminals created after setup;
existing terminal objects retain their resolved position and original options.
Position-appropriate Snacks options such as `height` may also be supplied.

New managed terminals have these buffer-local mappings in both Normal and
Terminal modes:

    NAME          KEY       ACTION
    term_new      <D-n>     require("terminals").new()
    term_close    <D-w>     require("terminals").close()
    term_prev     <D-{>     require("terminals").prev()
    term_next     <D-}>     require("terminals").next()

These stable names are snacks.win `keys` entries. Defaults are merged before
user-provided `win.keys`, so each one may be replaced or set to false without
installing a global mapping. For example: >lua

    require("terminals").setup({
      win = {
        keys = {
          term_new = {
            "<leader>tn",
            function()
              require("terminals").new()
            end,
            mode = { "n", "t" },
            desc = "New terminal",
          },
          term_close = false,
        },
      },
    })
<

Unrelated custom `win.keys` entries are preserved. The following invariants
are applied last and cannot be overridden: the resolved creation position,
configured width, disabled folding with manual fold method, the managed
`win.wo.winbar` expression, and no Normal-mode q mapping. A per-call position
wins over `win.position`. A user-provided `win.wo.winbar` is replaced. Escape
handling uses the Snacks defaults; terminals.nvim does not supply Escape
mappings.

==============================================================================
COMMANDS                                                *terminals-commands*

                                                       *:TermNew* *TermNew*
:TermNew [command...]
    Create, select, and focus a new terminal. Arguments are forwarded as one
    shell string. With no arguments, use the shell configured by Snacks.

                                                   *:TermClose* *TermClose*
:TermClose
    Destroy the focused managed terminal. Do nothing when the current window
    is not a managed terminal.

                                                       *:TermPrev* *TermPrev*
:TermPrev
    Circularly select and focus the previous terminal for the applicable
    directory and position group. Do nothing when that group has no terminals.

                                                       *:TermNext* *TermNext*
:TermNext
    Circularly select and focus the next terminal for the applicable directory
    and position group. Do nothing when that group has no terminals.

                                                   *:TermToggle* *TermToggle*
:TermToggle
    Hide or show the selected terminal for the applicable directory and
    position group. Create a shell terminal when that group has no terminals.

    Commands take no position arguments. They inherit the focused managed
    terminal's position, or use the configured default outside one.

==============================================================================
LUA API                                                    *terminals-api*

setup({opts})                                     *terminals.setup()*
    Configure terminals created in the future. {opts.width} is an integer and
    {opts.win} is a table of Snacks window options. {opts.win.position} sets
    the default position. Returns nothing.

new({cmd}, {opts})                                   *terminals.new()*
    Create and select a terminal. Focus it when its resolved directory matches
    the applicable current directory; otherwise start it hidden. {cmd} may be
    a shell string, an argv list, or nil. {opts} is optional. {opts.title}
    sets a persistent winbar title, and {opts.cwd} sets the process working
    directory. {opts.position} sets the window position and completes the
    terminal-group scope. Returns the new Snacks terminal object. For example:
    >lua

        require("terminals").new("npm test", {
          cwd = "../app",
          position = "right",
          title = "Tests",
        })
<

    {opts.cwd} may be absolute or relative. Absolute paths are normalized
    without resolving symbolic links. Relative paths use the focused managed
    terminal's group as their base, or Neovim's current directory outside a
    managed terminal. Without {opts.cwd}, new() uses that same base directory.
    The resolved absolute directory is passed to Snacks as `cwd` and forms the
    directory portion of the group key.

    {opts.position} may be "float", "top", "bottom", "left", or "right".
    Without it, new() inherits a focused managed terminal's position, or uses
    setup's `win.position` outside one. The resolved position is stored at
    creation and is unaffected by later setup calls. :TermNew has no custom
    directory or position syntax; use this Lua API instead.

    If the resolved directory differs from the captured base, the process
    starts as its target group's active selection, but its window stays hidden
    and current visible windows remain in place. Toggling from the target
    directory later reveals the same terminal. If the directories match,
    new() replaces a visible terminal only at the target position and focuses
    the new one. An explicit different position therefore opens in the
    foreground while edge terminals elsewhere remain open. :TermNew and the
    default new-terminal mapping inherit the focused scope and remain
    foreground operations.

close()                                            *terminals.close()*
    Destroy the focused managed terminal and return its Snacks object. Returns
    nil outside a managed terminal.

prev({opts})                                        *terminals.prev()*
next({opts})                                        *terminals.next()*
    Circularly select and focus a terminal for the applicable directory and
    position group. {opts} is optional; {opts.position} targets a position.
    Without it, use the focused managed terminal's position, or the configured
    default outside one. Return the Snacks object, or nil when the exact group
    has no terminals.

toggle({opts})                                    *terminals.toggle()*
    Hide or show the selected terminal and return its Snacks object. {opts} is
    optional; {opts.position} targets a position using the same resolution as
    prev() and next(). If that exact group is empty, create and return a new
    shell terminal at the resolved position.

==============================================================================
BEHAVIOR                                               *terminals-behavior*

Each `(normalized cwd, position)` pair owns an ordered group and active
selection. Directories are normalized without resolving symbolic links. While
a managed terminal is focused, actions use its directory and, unless
explicitly targeted, its position. Outside a managed terminal they use
vim.fn.getcwd() and the configured default position at invocation. Commands
use this implicit resolution. The registry itself is global, so all tab pages
share the groups.

An explicit {opts.cwd} changes both the new process directory and its group.
Relative values are resolved from the focused terminal's group, or from
vim.fn.getcwd() outside a managed terminal. Absolute values are normalized
directly. Without {opts.cwd}, a new terminal inherits the focused terminal's
group or uses vim.fn.getcwd() outside one. Equivalent normalized absolute
paths share a group only when the resolved position also matches.

Creating a terminal whose resolved directory matches the applicable directory
hides any visible terminal at its target position, then shows and focuses the
new one. Terminals at other edge positions remain open. If the directories
differ, the new terminal starts hidden as the target group's active selection,
preserving the current window and all visible managed terminals. Selecting or
toggling a terminal replaces visibility only within its target position.

Leaving a managed float hides only that window. Edge-positioned terminals stay
visible when focus moves elsewhere. Hiding always retains the buffer and
terminal process; selecting it again restores the same Snacks object.

Every managed terminal has a left-aligned winbar listing its exact directory
and position group's terminals in creation order. A non-nil {opts.title},
including an empty string, is authoritative for that terminal's lifetime.
Otherwise, the title comes from the terminal's creation command. Shell strings
are displayed directly, argv lists are joined with single spaces without shell
quoting, and a terminal created without a command is labeled `terminal`. The
selected title uses WinBarNameActive; other titles use WinBarName. Each title
has one highlighted padding space on both sides. A retained terminal that
exits with a non-zero status appends its numeric code directly after its
title, with one padding space on both sides highlighted by TermBarStatus.
Separators and all remaining winbar space use NormalFloat. WinBarName,
WinBarNameActive, TermBarStatus, TermBarAttention, and NormalFloat are
consumed without being defined or overridden.

An OSC 9 notification from an unfocused managed terminal appends a padded !
box after that terminal's exit-status box, highlighted by TermBarAttention.
Repeated notifications retain one mark, and focusing the terminal clears it.
Notifications emitted while the terminal is focused are ignored. OSC 9;4
progress sequences and unrelated terminal requests do not set attention. The
notification text is discarded.

Wiping a terminal buffer removes the corresponding object from the registry.
TermClose closes the object and terminates its process without reporting the
expected process termination as an error. The Lua close() API and default
<D-w> mapping are silent in the same way. A spontaneous non-zero process exit
still reports an error and preserves the terminal for inspection; a zero exit
closes and removes it.

When the removed terminal was focused, its immediate predecessor in creation
order from the same directory and position is selected and focused. If there
is no predecessor, its immediate successor from that exact group is used. A
fallback is never selected from another directory or position. Removing a
background terminal does not change focus. If the group becomes empty, focus
remains in Neovim's remaining window and no replacement terminal is created.

No global mappings are installed. Managed terminal buffers use the
configurable action mappings described in |terminals-setup| and inherit
Snacks' default Escape handling.
