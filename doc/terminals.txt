INTRODUCTION                                        *terminals-introduction*

terminals.nvim manages the persistent window objects returned by Snacks
Terminal. Terminals are ordered by creation time and selected circularly.
Every terminal belongs permanently to the tabpage where it was created. Each
owner tabpage, normalized working directory, and window position combination
has an independent terminal group and active selection.

==============================================================================
REQUIREMENTS                                        *terminals-requirements*

Snacks is a required dependency:

    https://github.com/folke/snacks.nvim

For lazy.nvim (replace OWNER with the repository owner): >lua

    {
      "OWNER/terminals.nvim",
      dependencies = { "folke/snacks.nvim" },
      opts = {},
    }
<

==============================================================================
SETUP                                                      *terminals-setup*

Setup is optional. The defaults are: >lua

    require("terminals").setup({
      position = "float",
    })
<

The top-level `position` setting may be "float", "top", "bottom", "left", or
"right". Snacks' buffer-replacing "current" position is not part of the
supported contract. Configuration affects terminals created after setup;
existing terminal objects retain their resolved position. A per-call position
wins over a focused managed terminal's position, which wins over the
configured default.

The former `win` configuration field has been removed. This is a breaking API
change: setup no longer accepts window dimensions, callbacks, window-local
options, or key overrides. terminals.nvim owns the Snacks window options it
passes, while Snacks provides the initial window dimensions. Left and right
terminal windows remain resizable. Their live widths are retained
independently per tabpage and side after resizing when managed terminals are
created, selected, hidden, or restored.

New managed terminals have these fixed buffer-local mappings in both Normal
and Terminal modes:

    NAME          KEY       ACTION
    term_new      <D-n>     require("terminals").new()
    term_close    <D-w>     require("terminals").close()
    term_prev     <D-{>     require("terminals").prev()
    term_next     <D-}>     require("terminals").next()

These mappings cannot be replaced or disabled through plugin configuration.
The manager also disables the Snacks Normal-mode q mapping, disables folding
with a manual fold method, and installs its managed winbar expression. Every
managed terminal position (float, top, bottom, left, and right) receives only
Normal:NormalFloat and NormalNC:NormalFloat through `winhighlight`, so focused
and inactive terminal windows use the same background. Left and right terminals
enforce `winfixwidth = false`. Escape handling uses the Snacks defaults;
terminals.nvim does not supply Escape mappings. No global
mappings are installed.

==============================================================================
COMMANDS                                                *terminals-commands*

                                                       *:TermNew* *TermNew*
:TermNew [command...]
    Create, select, and focus a new terminal. Arguments are forwarded as one
    shell string. With no arguments, use the shell configured by Snacks.

                                                   *:TermClose* *TermClose*
:TermClose
    Destroy the focused managed terminal. Do nothing when the current window
    is not a managed terminal.

                                                       *:TermPrev* *TermPrev*
:TermPrev
    Circularly select and focus the previous terminal for the current tab's
    applicable directory and position group. Do nothing when that group has no
    terminals.

                                                       *:TermNext* *TermNext*
:TermNext
    Circularly select and focus the next terminal for the current tab's
    applicable directory and position group. Do nothing when that group has no
    terminals.

                                                   *:TermToggle* *TermToggle*
:TermToggle
    Hide or show the selected terminal for the current tab's applicable
    directory and position group. Create a shell terminal when that group has
    no terminals.

    TermClose, TermPrev, TermNext, and TermToggle take no position arguments.
    They inherit the focused managed terminal's position, or use the
    configured default outside one.

                                                       *:TermSend* *TermSend*
:[range]TermSend [position]
    From a characterwise or linewise Visual selection, focus a managed
    terminal and insert the selected file location without a newline.
    {position} is optional and may be "float", "top", "bottom", "left", or
    "right". Position completion is provided. See |terminals.send()| for
    targeting, formatting, and errors.

==============================================================================
LUA API                                                    *terminals-api*

setup({opts})                                     *terminals.setup()*
    Configure terminals created in the future. {opts.position} sets the
    default position and may be "float", "top", "bottom", "left", or "right".
    The default is "float". The former {opts.win} field has been removed;
    window and mapping behavior is plugin-owned. Returns nothing.

new({cmd}, {opts})                                   *terminals.new()*
    Create and select a terminal. Focus it when its resolved directory matches
    the applicable current directory; otherwise start it hidden. {cmd} may be
    a shell string, an argv list, or nil. {opts} is optional. {opts.title}
    sets a persistent winbar title, {opts.cwd} sets the process working
    directory, and {opts.env} sets a per-creation process environment.
    {opts.position} sets the window position and completes the terminal-group
    scope within the current tab. Returns the new Snacks terminal object. For
    example:
    >lua

        require("terminals").new("npm test", {
          cwd = "../app",
          position = "right",
          title = "Tests",
          env = { NODE_ENV = "test" },
        })
<

    {opts.cwd} may be absolute or relative. Absolute paths are normalized
    without resolving symbolic links. Relative paths use the focused managed
    terminal's group as their base, or Neovim's current directory outside a
    managed terminal. Without {opts.cwd}, new() uses that same base directory.
    The resolved absolute directory is passed to Snacks as `cwd` and forms the
    directory portion of the group key.

    {opts.env} is an optional string-to-string table passed to Snacks for the
    spawned process. It applies only to this terminal creation. When omitted,
    it remains nil so the process uses the usual Snacks/Neovim environment
    inheritance.

    {opts.position} may be "float", "top", "bottom", "left", or "right".
    Without it, new() inherits a focused managed terminal's position, or uses
    setup's `position` outside one. The resolved position is stored at
    creation and is unaffected by later setup calls. :TermNew retains its
    command-only syntax and has no custom directory, position, or environment
    syntax; use this Lua API instead.

    If the resolved directory differs from the captured base, the process
    starts as its current-tab target group's active selection, but its window
    stays hidden and current visible windows remain in place. Toggling from
    the target directory in that owner tab later reveals the same terminal. If
    the directories match, new() replaces a visible terminal only at the
    target position in the current tab and focuses the new one. An explicit
    different position therefore opens in the foreground while edge terminals
    elsewhere,
    including other tabs, remain open. :TermNew and the default new-terminal
    mapping inherit the focused scope and remain foreground operations.

close()                                            *terminals.close()*
    Destroy the focused managed terminal and return its Snacks object. Returns
    nil outside a managed terminal.

prev({opts})                                        *terminals.prev()*
next({opts})                                        *terminals.next()*
    Circularly select and focus a terminal for the current tab's applicable
    directory and position group. {opts} is optional; {opts.position} targets
    a position. Without it, use the focused managed terminal's position, or
    the configured default outside one. Return the Snacks object, or nil when
    the exact current-tab group has no terminals.

toggle({opts})                                    *terminals.toggle()*
    Hide or show the selected terminal and return its Snacks object. {opts} is
    optional; {opts.position} targets a position using the same resolution as
    prev() and next(). If that exact current-tab group is empty, create and
    return a new shell terminal at the resolved position.

send({opts})                                        *terminals.send()*
    Capture the active characterwise or linewise Visual selection, focus a
    managed terminal, and insert its formatted file location through the
    terminal buffer channel. No newline is appended, so the reference is not
    submitted. {opts} is optional; {opts.position} may be "float", "top",
    "bottom", "left", or "right".

    Without {opts.position}, all managed terminals with valid windows in the
    current tab are candidates, regardless of cwd or focus. Exactly one is
    focused and used. No candidates reports an error without creating a
    terminal; multiple candidates reports ambiguity and requires a position.

    With {opts.position}, a visible terminal at that position in the current
    tab is used even if it belongs to another cwd. If none is visible there,
    send() restores the active terminal in the current tab's applicable
    `(cwd, position)` group. It creates and focuses a shell terminal at that
    position only when the exact current-tab group is empty. The applicable
    cwd follows the same scope resolution used by toggle(). Terminals in other
    tabs are ignored.

    The location is relative to the target terminal's cwd. Endpoints are
    inclusive and columns are 1-based byte columns: >

        path:line
        path:start_line-end_line
        path:start_line:start_col-end_line:end_col
<
    Reversed selections are normalized. A characterwise selection covering
    complete lines uses the shorter linewise form. Paths outside the target
    cwd may begin with `../`.

    On success, return the focused Snacks terminal. Return nil and notify for
    an invalid position, unsupported blockwise selection, missing or invalid
    Visual marks, unnamed buffer, incompatible filesystem roots, invalid
    terminal channel, or failed channel write. Selection and targeting errors
    send no input. Channel errors occur after the target has been focused.

==============================================================================
BEHAVIOR                                               *terminals-behavior*

Each `(owner tabpage, normalized cwd, position)` combination owns an ordered
group and active selection. Directories are normalized without resolving
symbolic links. While a managed terminal is focused, actions use its directory
and, unless explicitly targeted, its position. Outside a managed terminal they
use vim.fn.getcwd() and the configured default position at invocation.
Commands use this implicit resolution in the current tab. Terminal objects,
lists, and selections are never shared or adopted across tabpages.

An explicit {opts.cwd} changes both the new process directory and its group.
Relative values are resolved from the focused terminal's group, or from
vim.fn.getcwd() outside a managed terminal. Absolute values are normalized
directly. Without {opts.cwd}, a new terminal inherits the focused terminal's
group or uses vim.fn.getcwd() outside one. Equivalent normalized absolute
paths share a group only when both the owner tabpage and resolved position
also match.

Creating a terminal whose resolved directory matches the applicable directory
hides any visible terminal at its target position in the current tab, then
shows and focuses the new one. Terminals at other edge positions and all edge
windows in other tabs remain open. If the directories differ, the new terminal
starts hidden as the current tab's target-group active selection, preserving
the current window and all visible managed terminals. Selecting or toggling a
terminal replaces visibility only within its owner tab and target position.

Leaving a managed float hides only that window. Switching tabs from a focused
float therefore hides it; returning to its owner tab and toggling restores the
same Snacks object. Edge-positioned terminals stay visible across focus and
tab changes. Hiding always retains the buffer and terminal process.

Every managed terminal has a left-aligned winbar listing its exact owner-tab,
directory, and position group's terminals in creation order. A non-nil
{opts.title}, including an empty string, is authoritative for that terminal's
lifetime. Otherwise, the title comes from the terminal's creation command.
Shell strings
are displayed directly, argv lists are joined with single spaces without shell
quoting, and a terminal created without a command is labeled `terminal`. The
selected title uses TermBarNameFocused when its managed terminal window and
buffer are current, and TermBarNameActive otherwise, including when an edge
terminal remains visible after focus moves to an editor window. Other titles
use TermBarName. Titles remain in creation order, and each has one highlighted
padding space on both sides. A retained terminal that exits with a non-zero
status appends its numeric code directly after its title, with one padding
space on both sides highlighted by TermBarStatus. A dedicated one-cell gap
precedes the first title's padding. This leading gap, the separator space
between terminal entries, and the trailing winbar fill use TermBarGapFocused
when the rendered managed terminal window and buffer are current, and
TermBarGap otherwise. Thus, a visible edge terminal switches its gaps to
TermBarGap after focus moves to an editor while its selected entry remains
TermBarNameActive.
TermBarName, TermBarNameActive, TermBarNameFocused, TermBarStatus,
TermBarAttention, TermBarGap, and TermBarGapFocused are user-defined highlight
groups consumed without being defined or overridden. NormalFloat is also
consumed for managed terminal backgrounds and the defensive fill rendered for
a missing, unmanaged, or stale winbar target.

An OSC 9 notification issues an INFO notification. Its message may start with
<title>: to set the notification title and remove that prefix from the body.
Only the first colon is a separator. Surrounding title whitespace and leading
body whitespace are stripped; additional colons and trailing body whitespace
are preserved. The prefix is recognized only when its trimmed title is
non-empty. Otherwise, the complete message remains the body and the title is
terminals. An absent or empty resulting body becomes "a terminal needs
attention", including when a valid title was provided.

When emitted by an unfocused managed terminal, the notification also appends a
padded ! box after that terminal's exit-status box, highlighted by
TermBarAttention. Repeated notifications retain one mark, and focusing the
terminal clears it. Notifications emitted while the terminal is focused do not
set attention. OSC 9;4 progress sequences and unrelated terminal requests do
not issue notifications or set attention.

                                      *terminals-t-attention* *t:attention*
The plugin owns the boolean tabpage variable t:attention for use by custom
tablines. It is true when at least one valid terminal owned by that tabpage
has unread attention and its cwd matches the tabpage's normalized working
directory, across all terminal positions. It is false otherwise. A
tabpage-local :tcd directory takes precedence over the global directory.
Window-local :lcd directories are ignored. Tabpages that share a directory
still have independent attention state.

Wiping a terminal buffer removes the corresponding object from the registry.
TermClose closes the object and terminates its process without reporting the
expected process termination as an error. The Lua close() API and default
<D-w> mapping are silent in the same way. Closing a tabpage also intentionally
closes every terminal it owns, including hidden and failed terminals,
terminates running jobs, and wipes retained buffers without reporting expected
termination errors. Terminals in remaining tabs are unaffected. A spontaneous
non-zero process exit still reports an error and preserves the terminal for
inspection in Normal mode, so ordinary keypresses do not dismiss it. Restoring
the failed terminal or trying to re-enter Terminal mode keeps it in Normal
mode. A zero exit closes and removes the terminal. Ctrl+D is not remapped: it
sends EOF to the shell, and a resulting successful exit from a focused managed
shell uses the same adjacent-terminal handoff.

When the removed terminal was focused, including when Ctrl+D ended its shell,
its immediate predecessor in creation order from the same owner tab,
directory, and position is selected and focused. If there is no predecessor,
its immediate successor from that exact group is used. A fallback is never
selected from another tab, directory, or position.
When a visible but unfocused edge terminal exits successfully, the same
adjacent fallback is shown in its owner tab and the previously focused editor
or other window keeps focus. This also applies while the owner tab is
inactive, without switching the active tab or stealing focus. A hidden
terminal that exits successfully is removed without showing a fallback or
changing focus. If the group becomes empty, its position closes, focus remains
in Neovim's remaining window, and no replacement terminal is created.

TermSend captures its Visual selection and named source path before changing
windows. Without a position it considers only managed terminals in the current
tab whose windows are currently open; hidden terminal buffers are not
candidates. With a position, visibility is checked only in the current tab
before that tab's applicable directory group is restored or created. Delivery
always focuses the resolved current-tab terminal and writes the reference
directly with nvim_chan_send(), without a trailing newline.

No global mappings are installed. Managed terminal buffers use the fixed
action mappings described in |terminals-setup| and inherit Snacks' default
Escape handling.
