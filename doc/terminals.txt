==============================================================================
INTRODUCTION                                        *terminals-introduction*

terminals.nvim manages the persistent window objects returned by Snacks
Terminal. Terminals are ordered by creation time, selected circularly, and
shared across tab pages.

==============================================================================
REQUIREMENTS                                        *terminals-requirements*

Snacks is a required dependency:

    https://github.com/folke/snacks.nvim

For lazy.nvim (replace OWNER with the repository owner): >lua

    {
      "OWNER/terminals.nvim",
      dependencies = { "folke/snacks.nvim" },
      opts = {},
    }
<

==============================================================================
SETUP                                                      *terminals-setup*

Setup is optional. The defaults are: >lua

    require("terminals").setup({
      width = 220,
      win = {},
    })
<

`width` is the float width in characters. Snacks clamps it when necessary.
`win` accepts additional snacks.win float options. Options affect terminals
created after setup; existing terminal objects are unchanged.

New managed terminals have these buffer-local mappings in both Normal and
Terminal modes:

    NAME          KEY       ACTION
    term_new      <D-n>     require("terminals").new()
    term_close    <D-w>     require("terminals").close()
    term_prev     <D-{>     require("terminals").prev()
    term_next     <D-}>     require("terminals").next()

These stable names are snacks.win `keys` entries. Defaults are merged before
user-provided `win.keys`, so each one may be replaced or set to false without
installing a global mapping. For example: >lua

    require("terminals").setup({
      win = {
        keys = {
          term_new = {
            "<leader>tn",
            function()
              require("terminals").new()
            end,
            mode = { "n", "t" },
            desc = "New terminal",
          },
          term_close = false,
        },
      },
    })
<

Unrelated custom `win.keys` entries are preserved. The following invariants
are applied last and cannot be overridden: floating position, configured
width, disabled folding with manual fold method, the managed `win.wo.winbar`
expression, and no Normal-mode q mapping. A user-provided `win.wo.winbar` is
replaced. Escape handling uses the Snacks defaults; terminals.nvim does not
supply Escape mappings.

==============================================================================
COMMANDS                                                *terminals-commands*

                                                       *:TermNew* *TermNew*
:TermNew [command...]
    Create, select, and focus a new terminal. Arguments are forwarded as one
    shell string. With no arguments, use the shell configured by Snacks.

                                                   *:TermClose* *TermClose*
:TermClose
    Destroy the focused managed terminal. Do nothing when the current window
    is not a managed terminal.

                                                       *:TermPrev* *TermPrev*
:TermPrev
    Circularly select and focus the previous terminal for the applicable
    directory group. Do nothing when that group has no terminals.

                                                       *:TermNext* *TermNext*
:TermNext
    Circularly select and focus the next terminal for the applicable directory
    group. Do nothing when that group has no terminals.

                                                   *:TermToggle* *TermToggle*
:TermToggle
    Hide or show the selected terminal for the applicable directory group.
    Create a shell terminal when that group has no terminals.

==============================================================================
LUA API                                                    *terminals-api*

setup({opts})                                     *terminals.setup()*
    Configure terminals created in the future. {opts.width} is an integer and
    {opts.win} is a table of Snacks float options. Returns nothing.

new({cmd}, {opts})                                   *terminals.new()*
    Create, select, and focus a terminal. {cmd} may be a shell string, an argv
    list, or nil. {opts} is optional. {opts.title} sets a persistent winbar
    title, and {opts.cwd} sets the process working directory and terminal
    group. Returns the new Snacks terminal object. For example: >lua

        require("terminals").new("npm test", {
          cwd = "../app",
          title = "Tests",
        })
<

    {opts.cwd} may be absolute or relative. Absolute paths are normalized
    without resolving symbolic links. Relative paths use the focused managed
    terminal's group as their base, or Neovim's current directory outside a
    managed terminal. Without {opts.cwd}, new() uses that same base directory.
    The resolved absolute directory is passed to Snacks as `cwd` and used as
    the terminal-group key. :TermNew has no custom-directory syntax; use this
    Lua API instead.

close()                                            *terminals.close()*
    Destroy the focused managed terminal and return its Snacks object. Returns
    nil outside a managed terminal.

prev()                                              *terminals.prev()*
next()                                              *terminals.next()*
    Circularly select and focus a terminal for the applicable directory group.
    Return its Snacks object, or nil when the group has no terminals.

toggle()                                          *terminals.toggle()*
    Hide or show the selected terminal and return its Snacks object. If the
    applicable group is empty, create and return a new shell terminal.

==============================================================================
BEHAVIOR                                               *terminals-behavior*

Each terminal's resolved working directory owns an ordered group and an active
selection. Directories are normalized without resolving symbolic links. While
a managed terminal is focused, new(), prev(), next(), and toggle() operate on
that terminal's group. Outside a managed terminal they use vim.fn.getcwd() at
invocation. The registry itself is global, so all tab pages use the same
groups.

An explicit {opts.cwd} changes both the new process directory and its group.
Relative values are resolved from the focused terminal's group, or from
vim.fn.getcwd() outside a managed terminal. Absolute values are normalized
directly. Without {opts.cwd}, a new terminal inherits the focused terminal's
group or uses vim.fn.getcwd() outside one. Equivalent normalized absolute
paths therefore share a group, including creation order and active selection.

Before a terminal is focused, any other visible managed terminal is hidden.
Leaving a managed float also hides only that window. Hiding retains its buffer
and terminal process; selecting it again restores the same Snacks object.

Every managed float has a left-aligned winbar listing its directory group's
terminals in creation order. A non-nil {opts.title}, including an empty string,
is authoritative for that terminal's lifetime. Otherwise, the title comes from
the terminal's creation command. Shell strings are displayed directly, argv
lists are joined with single spaces without shell quoting, and a terminal
created without a command is labeled `terminal`. The selected title uses
WinBarNameActive; other titles use WinBarName. Each title has one highlighted
padding space on both sides. A retained terminal that exits with a non-zero
status appends its numeric code directly after its title, with one padding
space on both sides highlighted by TermBarStatus. Separators and all remaining
winbar space use NormalFloat. WinBarName, WinBarNameActive, TermBarStatus, and
NormalFloat are consumed without being defined or overridden.

Wiping a terminal buffer removes the corresponding object from the registry.
TermClose closes the object and terminates its process without reporting the
expected process termination as an error. The Lua close() API and default
<D-w> mapping are silent in the same way. A spontaneous non-zero process exit
still reports an error and preserves the terminal for inspection; a zero exit
closes and removes it.

When the removed terminal was focused, its immediate predecessor in creation
order is selected and focused. If there is no predecessor, its immediate
successor is used. Removing a background terminal does not change focus. If
the group becomes empty, focus remains in Neovim's remaining window and no
replacement terminal is created.

No global mappings are installed. Managed terminal buffers use the
configurable action mappings described in |terminals-setup| and inherit
Snacks' default Escape handling.
